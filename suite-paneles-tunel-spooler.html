Suite de scripting servers: el panel web de administracion del servidor, el panel web de administracion restringida, el daemon de tunel L2TP/IPsec y el spooler de impresion

Cuatro sinks de inyección en la familia miniserv + L2TP + el spooler de impresion, y el bypass de confianza X-SSL-Client-* con su alcance real: tres prerrequisitos que no son default.

📅 2026-09-02⏱ 20 min🏷 Vulnerability Research
// En 30 segundos
  • Cuatro sinks de command injection en la familia de scripting servers: el panel web de administracion del servidor, el panel web de administracion restringida (motor miniserv compartido), el daemon de tunel L2TP/IPsec (L2TP→scripts) y el spooler de impresion (la herramienta de configuracion de impresorasrip).
  • El hilo común: datos de red o de configuración sin sanear terminan en un sh -c — la superficie de scripts admin y helpers que el core ya endureció.
  • El trust-bypass X-SSL-Client-* es real pero condicional: exige trust_real_ip=1 + proxy en trusted_proxies + DN coincidente exacto con un certificado pre-registrado.
  • Lección: "común en producción" ≠ "config por defecto"; verificar siempre el valor real antes de declarar alcance pre-auth.

El hilo común: todos ejecutan un shell con datos que en algún punto provienen de la red o de un campo de configuración sin sanear. Es la clase de bug que el core de cada producto ha ido endureciendo, pero sobrevive en los scripts admin y los helpers — la superficie que el mantenimiento no mira.

02. 0x00 — el panel web de administracion del servidor cpan/el CGI de administracion

El módulo de instalación de módulos Perl de el panel web de administracion del servidor (CPAN) pasa los argumentos del usuario directamente a la apertura de un pipe de comandos:

perl
// cpan/el CGI de administracion:45 — el argumento del usuario entra a un comando
open(CMD, "..." . $module . " |") or die(...);
// un pipe "|" se ejecuta con /bin/sh -c; $module sin escapar => inyección
// Presente sin cambios desde hace muchos años (sink heredado/legacy)

El sink está en el cierre del pipe con |, que el intérprete ejecuta con /bin/sh -c. Un módulo como ;touch /tmp/x;# termina la parte "normal" y ejecuta lo inyectado. El alcance es post-auth: requiere una sesión válida de el panel web de administracion del servidor con privilegios de administrador (root). No es pre-auth.

03. 0x01 — el panel web de administracion restringida ssh/el CGI de administracion y el CGI de administracion

el panel web de administracion restringida comparte el motor miniserv con el panel web de administracion del servidor pero sirve a usuarios normales, no al admin. Tiene dos sinks de la familia:

perl
// ssh/el CGI de administracion:9/12 — el tipo ($type) se interpola sin quotemeta
$cmd = "..." . $type . " ...";
system($cmd);   // $type del usuario, sin escapar

// htaccess/el CGI de administracion:9 — open con pipe sobre input
open(FIND, "find ..." . $_ . " |") or die(...);
// $_ (dato del request) entra a un pipe sh -c sin quotemeta

Ambos son post-auth y, por defecto, corren con el uid del usuario de el panel web de administracion restringida (miniserv baja el euid): el RCE llega como un usuario no-root. La inyección es real, pero el impacto queda acotado a la cuenta del usuario autenticado salvo que la configuración eleve privilegios.

04. 0x02 — el daemon de tunel L2TP/IPsec L2TP → scripts ip-up

el daemon de tunel L2TP/IPsec es un servidor PPP/BGP/L2TP para BRAS y LNS de ISP. En su modo de compatibilidad pppd_compat ejecuta los scripts ip-up/ip-down con los campos de la sesión sin escapar. El AVP que llega sin sanear es el CALLING_SID (identificador llamante):

bash
// ip-up/ip-down — CALLING_SID ($6) se evalúa sin comillas
eval "$6";   // el AVP llamante del túnel L2TP entra a un eval

// Origen: el Calling-SID del paquete ICRQ L2TP (UDP 1701), 0-click
// con contenido: ;id > /tmp/x;# => ejecución en el script de sesión

Es un camino pre-auth y 0-click por UDP L2TP (puerto 1701): el túnel se inicia antes de autenticarse. La ejecución es root (los scripts ppp corren como root). La limitación real: requiere la config de compatibilidad pppd_compat con los scripts presentes, que no es la instalación por defecto pura.

05. 0x03 — el spooler de impresion: el spooler de impresion-browsed → la herramienta de configuracion de impresorasrip

el spooler de impresion es el sistema de impresión estándar. El daemon el spooler de impresion-browsed descubre impresoras de red y, al procesar trabajos, deriva el filtro la herramienta de configuracion de impresorasrip, que ejecuta con un shell:

bash
// el spooler de impresion-browsed → la herramienta de configuracion de impresorasrip → sh -c
// El perfil de color (cupsICCProfile) se pasa fuera del allowlist
// y se interpola en el comando del filtro:
sh -c "... la herramienta de configuracion de impresoras-rip ..."  // perfil no validado => inyección

// Origen: perfil manipulado vía descubrimiento el spooler de impresion-browsed
// (ya cubierto por la familia CVE-2024-47177 — variante allowlist)

El vector es el descubrimiento de impresoras de red: un perfil fuera del allowlist del mantenedor se interpola en el comando del filtro. Ejecuta como lp (usuario del sistema de impresión). Alcance: una LAN con impresión en red (el spooler de impresion-browsed activo), no Internet de forma directa.

06. 0x04 — El bypass de confianza X-SSL-Client-*

el panel web de administracion del servidor/el panel web de administracion restringida validan la autenticación por cliente SSL. En despliegues detrás de un reverse proxy, el motor miniserv confía en las cabeceras X-SSL-Client-* que el proxy inyecta para indicar el certificado del cliente:

perl
// miniserv-lib.pl — confianza en las cabeceras SSL del proxy
$header{"X-SSL-Client-DN"}, $header{"X-SSL-Client-Cert"} ...
// se usan para resolver el usuario por certificado (find_user_by_cert)

La clase de riesgo conceptual: si el motor no distingue una cabecera inyectada por el atacante de una inyectada por el proxy, los sinks post-auth de la familia podrían volverse pre-auth por composición. Tras validación rigurosa, el alcance real en config estándar es limitado:

  • Requiere trust_real_ip=1 en miniserv.conf (opt-in del admin para reverse proxy).
  • El peer IP del cliente debe estar dentro de trusted_proxies; si no, el motor borra esas cabeceras.
  • El X-SSL-Client-DN espoofeado debe coincidir exacto con un certificado pre-registrado a un usuario en find_user_by_cert — no es un bypass ciego fabricable a voluntad.
⚠
Nota de honestidad técnica

Con los tres prerrequisitos activos, el bypass sí convierte los sinks post-auth en pre-auth. Pero ninguna es el valor por defecto: son cambios que un admin habilita para operar tras un reverse proxy. La lección general es verificar siempre el valor real de la configuración por defecto antes de declarar una clase de alcance: "común en producción" no es lo mismo que "config por defecto".

✓
Divulgación responsable

Se publican con fines de hardening y concienciación. Mitigación común a toda la familia: nunca interpolar datos de red o de request en un shell — quotemeta/escapado en Perl para la familia miniserv, no derivar comandos por eval en los scripts ppp, y validar los perfiles contra el allowlist en el spooler de impresion. Cada caso comunicado al mantenedor como parte del proceso responsable.
