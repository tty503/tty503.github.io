libarchive: uninitialized heap read en CAB/LZX cazado con patch-diffing

Mismo CAB, dos builds: la vulnerable extrae leyendo un history guard sin inicializar; la parcheada rechaza con LZX_CORRUPT. El patch-diffing como radar de zonas calientes y una clasificación honesta: DUP-RACE.

2026-08-2111 minVulnerability Research

Resumen. Mismo archivo CAB, dos binarios: el snapshot de bsdtar 3.8.9 extrae leyendo un history guard del decoder LZX que nadie inicializó (CWE-457); el build con fix lo rechaza con LZX_CORRUPT. Método: patch-diffing como radar — un commit upstream del 08-08 endureció el path CAB/LZX y la revisión periódica del snapshot reveló que el fix no estaba. Validación A/B: mismo input, única variable = el parche. Vulnerable rc=0 (ASAN use-of-uninitialized-value); parcheado rc=1 (-25). Clasificación honesta: DUP-RACE — el fix ya existía una semana antes. El activo duradero es el método, no el CVE.

Resumen

bsdtar extrae un CAB LZX leyendo como guardián un valor de memoria no inicializada. Al recibir el mismo CAB, el snapshot vulnerable procede (rc=0) y el build parcheado lo rechaza como corrupto — la diferencia es un commit de endurecimiento previo. Se documenta como DUP-RACE: el fix se anticipó por otra vía, pero el hallazgo verifica la validez del método radar de patch-diffing sobre snapshots.

Ficha técnica

Ficha técnica. Target: libarchive / bsdtar 3.8.9 — CAB + compresión LZX. Clase: Use of Uninitialized Variable — CWE-457. Sink: lzx_read_blocks (history guard) durante la extracción. Validación: ASAN ( use-of-uninitialized-value ) + valgrind --track-origins=yes. A/B: Vulnerable rc=0 · Parcheado rc=1 (LZX_CORRUPT). Clasificación: DUP-RACE — fix upstream anterior a la detección.

Veredicto. No es un 0-day: es un caso metodológico. El patch-diffing sobre snapshots demostró detectar divergencias reales; el valor entregado es ese método, no un CVE sellable.
