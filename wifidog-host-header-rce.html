wifidog RCE root: cabecera Host → iptables (CWE-78)

Request HTTP pre-auth con cabecera Host maliciosa termina en execvp(/bin/sh, -c) que construye iptables. Reverse shell root verificada. Sink fw_iptables.c:596 → util.c:96.

2026-09-0217 minVulnerability Research
// En 30 segundos
  • RCE pre-auth con 1 sola petición HTTP (puerto 2060): la cabecera Host inyecta argumentos en execvp("/bin/sh","-c") → reverse shell como root (uid=0).
  • Cadena real: api.c:462 → http.c:140/154 → fw_iptables.c:596 → util.c:96 — el Host entra en un comando de firewall construido con concatenación.
  • Requisito de config real en OpenWrt: una FirewallRuleSet global debe existir (presente en configuraciones reales de fw3).
  • CWE-78. Sin CVE asignado al cierre del análisis.

01. Resumen

Wifidog (uno de los auth/redirect daemons más usados en firmware embebido) arma reglas de iptables concatenando una cadena proveniente de la cabecera Host de la petición. El valor no se valida, y con un Host "inteligente" se rompe el comando y se encadena un payload shell ejecutado por execvp. Reproducción: un único request HTTP hacia el puerto 2060 dispara la reverse shell.

La verificación cubrió la ruta completa entrada→sink (archivo:línea reales de libhttpd, que es el servidor HTTP embebido incluido en el fuente), sobre el árbol actual sin .git y sin consultar ninguna base de CVEs previa.
