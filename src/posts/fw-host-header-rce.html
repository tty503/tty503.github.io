Resumen. RCE pre-auth con 1 sola petición HTTP (puerto 2060): la cabecera Host llega sin validar a la construcción de una regla de firewall que termina en un intérprete de comandos (uid del proceso). El valor del Host termina concatenado en la construcción de una regla de firewall. Requisito de config real en la distribucion de firmware: una FirewallRuleSet global debe existir (presente en configuraciones reales de fw3). CWE-78. Sin CVE asignado al cierre del análisis.

Resumen

el daemon de autenticacion y redireccion (uno de los auth/redirect daemons más usados en firmware embebido) arma reglas de iptables concatenando una cadena proveniente de la cabecera Host de la petición. El valor no se valida, y con un Host malformado se rompe la construcción del comando y se puede forzar la ejecución de comandos. Reproducción: un único request HTTP hacia el puerto 2060 dispara la ejecución de comandos.

La verificación cubrió la ruta completa entrada→sink (archivo:línea reales de libhttpd, que es el servidor HTTP embebido incluido en el fuente), sobre el árbol actual sin .git y sin consultar ninguna base de CVEs previa.

Ficha técnica

Ficha técnica. Target: el daemon de autenticacion y redireccion (daemon captive portal, libhttpd embebido). Clase: OS command injection — CWE-78. Acceso: Pre-auth · 1 petición HTTP · puerto 2060. Vector: Cabecera Host → comando iptables → un intérprete de comandos. Ruta documentada en el artículo original. Impacto: ejecución de comandos como administrador (uid del proceso). Config: Requiere FirewallRuleSet global (real en fw3/la distribucion de firmware). Fix: Sin CVE asignado al cierre.

Veredicto. RCE pre-auth reproducible con evidencia E2E (3/3): ejecución de comandos como administrador en la distribucion de firmware. El único matiz es la dependencia de una regla de firewall global, que forma parte de la configuración por defecto de los firmwares que lo integran.
