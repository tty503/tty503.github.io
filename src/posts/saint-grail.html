01. Motivación: el bug hunting no es un sprint

Durante años, colegas me han sugerido meterse de lleno al bug hunting. Y la idea es tentadora. Pero cualquiera que haya intentado vivir de esto sabe que los años de investigación no siempre se traducen en ingresos estables: fuga de cerebros hacia las FAANG, competencia feroz, y un solo bug puede llevarte semanas sin garantía de recompensa — la ecuación no es sencilla.

La inquietud por explorar vulnerabilidades, sin embargo, nunca desapareció. Lo que necesitaba era un sistema que multiplicara mi capacidad de investigación: documentar cada paso, visualizar relaciones entre componentes e integrar IA para acelerar el proceso. Así nació SAINT GRAIL.

📊
Nota sobre los datos

Todas las capturas y datos de este artículo son de prueba, usando un conjunto genérico (un programa ficticio llamado «GenericApp») para no exponer la investigación real. La plataforma es completamente funcional, pero los vectores, fases y primitivas visibles son placeholders.

02. ¿Qué es SAINT GRAIL?

Una plataforma modular para documentar, visualizar y ejecutar investigaciones de seguridad ofensiva. Combina API REST con SurrealDB embebida, frontend de grafo interactivo y utilidades CLI — todo editable directamente, sin dependencias de frameworks pesados. El objetivo: un copiloto de investigación que no reemplace al analista, sino que lo potencie.

  • Crear vectores de ataque a partir de hallazgos en proyectos open-source.
  • Generar preguntas contextuales con DeepWiki para profundizar en componentes específicos.
  • Clasificar respuestas con IA (DeepSeek en mis pruebas) y crear automáticamente primitivas explotables.
  • Ejecutar PoCs y registrar resultados en un ciclo de mejora continua.
  • Visualizar el progreso en un grafo interactivo: fases, vectores, brechas y primitivas.
🔧
¿Por qué no es público todavía?

El sistema aún no está lo bastante maduro para liberarlo como open-source: piezas por pulir, documentación y pruebas de estrés pendientes. Comparto los avances porque la comunidad puede beneficiarse de las ideas, aunque el código no esté listo para consumo masivo.

03. Arquitectura y componentes

La plataforma sigue KISS (Keep It Simple, Stupid) y la filosofía Unix: cada módulo tiene una responsabilidad única y se comunica por APIs bien definidas.

tree

saint-grail/
├── api/                    # Backend Flask + SurrealDB
│   ├── server.py           # Arranque de la app Flask
│   ├── storage.py          # Capa de persistencia (SurrealDB)
│   ├── llm.py              # Cliente DeepSeek, token budget
│   ├── deepwiki.py         # Generación de preguntas DeepWiki
│   └── routes/
│       ├── agent.py        # Agente híbrido (bucle DeepWiki)
│       ├── ingest.py       # Ingesta de datos, PoC
│       └── ...
├── graph/                  # Frontend del grafo (HTML5 Canvas)
├── admin/                  # Dashboard de administración
├── utils/                  # Scripts auxiliares (fetch_commits, etc.)
├── config/
│   └── saint-grail.conf    # Configuración global (tokens, GitHub)
└── data/                   # Base de datos SurrealDB + JSONs

Backend y base de datos

La API usa Flask con SurrealDB en modo embebido: sin servidor de base de datos externo, todo en un archivo local. La taxonomía de nodos del grafo:

KindForma en el grafoDescripción
phaseCuadradoFases de la cadena de ataque
vectorCírculoVectores de ataque específicos
primitiveTriánguloPrimitivas explotables (addr_of, fake_obj, etc.)
barrierRomboBrechas o bloqueantes
researchRectánguloPreguntas DeepWiki o referencias externas

La API expone CRUD de datos, ingesta de hallazgos desde DeepWiki, creación/ejecución de PoCs, sincronización P2P entre instancias y el ciclo completo del agente híbrido.

Orquestador y línea de comandos

Todo se controla desde saint_grail.sh, un orquestador Bash que inicia servicios, muestra estado, ejecuta el agente y monitoriza el presupuesto de tokens de DeepSeek.

04. El agente híbrido y DeepWiki

La característica más potente: el agente híbrido de investigación, un ciclo donde la IA y el analista se complementan:

  1. Selección automática: el bucle toma el primer vector activo que no esté en un estado final.
  2. Generación de preguntas DeepWiki: deepwiki.py crea preguntas contextuales en español según componente, archivos de auditoría y tipo de vector. Ejemplo: «En el canal IPC, ¿se validan los tamaños de los mensajes antes de asignar buffers? ¿Es posible enviar un mensaje manipulado que provoque corrupción de memoria?»
  3. Intervención humana: el nodo se pausa en AWAITING_DEEPWIKI y las preguntas aparecen en el dashboard; el analista investiga y responde.
  4. Clasificación y acción: /api/agent/deepwiki/answer clasifica el riesgo con DeepSeek (o por palabras clave si el presupuesto de tokens está agotado). Riesgo alto → nuevo nodo primitive automático, PoC generado y ejecutado.
🤖
DeepSeek como LLM de pruebas

Usé DeepSeek (modelo gratuito con límite diario de tokens) para toda la integración. La plataforma es agnóstica al proveedor: cualquier API compatible con OpenAI se configura en saint-grail.conf.

06. Estado actual y próximos pasos

SAINT GRAIL ya es funcional en mi entorno de desarrollo: el agente híbrido genera preguntas, el dashboard permite responderlas, se crean primitivas automáticamente y los PoCs se ejecutan. Aún no está listo para producción ni para un repo público. Tareas pendientes:

  • Completar la ejecución real de PoCs (hoy simulada en muchos endpoints).
  • Migrar de los generadores Bash (gen_*.sh) a una estructura de proyecto estable — aunque han sido increíblemente útiles para prototipado rápido.
  • Mejorar la UI/UX del dashboard para hacer el flujo más intuitivo.
  • Añadir tests automatizados para el ciclo completo del agente híbrido.
  • Explorar integraciones con otros modelos más allá de DeepSeek.
🚀
¿Cuándo será público?

Cuando el código esté en un estado digno de compartir — no me gusta liberar proyectos a medias. Mientras tanto, este artículo y las actualizaciones del blog son el canal.

Lo que más me entusiasma es el potencial de DeepWiki como fuente de contexto: generar preguntas específicas sobre archivos de código, commits y componentes abre una investigación semi-automatizada que no he visto en otras herramientas. No se trata de reemplazar al analista, sino de darle superpoderes.
